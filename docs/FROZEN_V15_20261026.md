The user narrowed this takeover to testing the historical KB first; further KB-loop
iterations follow later. This is a public-benchmark readout, not a fresh generalization
experiment. No model weights, claims, historical runs, RL runtime or remote processes
are changed. No sealed final benchmark test is opened.

## Measurement

Require all question × arm × repeat cells before opening the grader. Missing
transport outcomes stop the experiment rather than shrinking the scoring denominator.
Malformed or truncated actual model answers are retained and scored zero.

Average repetitions within each question. Report accuracy, all three paired
contrasts, group-cluster standard errors and fixed-seed group bootstrap 95% intervals.
Retain per-question and per-family results. Citation/opening associations are usage
telemetry; they do not identify the causal effect of an individual claim.

Published leaderboard scores are descriptive context only: their exact solver
budgets and paired predictions have not been matched. The existing local 76.2%
35-claim result belongs to a different `aiq_loop` implementation/model contract;
it is neither this run's result nor evidence for the final 143-claim KB.

## Execution scheduling amendment

Before opening any scores, observed mean request latency was about 11 seconds.
The initial six-worker dispatch was safely stopped with STOP and its in-flight
responses saved. A separately committed `frozen_execution.py` and hashed
`execution-amendment.json` authorize 24 workers for the same frozen request grid.
The original registration, evaluator source, cache identity, prompts and per-task
budgets remain the comparison contract. A hashed phase-one prefix records every
saved response/prediction before handover. The final report must disclose both
dispatch phases and failures; no phase is selected using correctness.

## Transport repair and return to six workers

The 24-worker phase stopped after 439 complete predictions and 675 primary call
slots. Two calls had unknown transport outcomes and no saved raw response. No
grader or accuracy was opened. `FROZEN_V15_TRANSPORT_RECOVERY_20261026.json` pins
the exact request/status/payload hashes and a second scheduling amendment.

With STOP present, `frozen_recovery.py` permits one additional physical attempt
for each of these two exact payloads. It archives each original request and failed
status before writing a durable repair raw, then lets the frozen evaluator resume
from those saved bytes. Successful raw responses and completed predictions must
remain byte-for-byte unchanged. A failed repair stops without automatic retry.
The additional physical attempts count against a conservative worst-case proof
of the original total request ceiling, including the parent's failed 401 call.
Unknown completion reservations (5,777 for the two original transport failures
and 3,000 for the parent) remain in the cost ledger after successful repair.

`execution-amendment-v2.json` restores six workers with a separately archived
controller, freeze and status. The original evaluator, all model inputs, the
phase-one prefix and the stopped 24-worker records remain intact. An additional
phase-two prefix pins 439 predictions, 673 successful raw responses and their
request/status records before repair.

The primary readout remains the full 500-question grid. Also report a separate
498-question sensitivity excluding both question IDs with any physical retry;
those tasks exceeded their original per-prediction physical-attempt limit even
though the prediction token/call chain is unchanged. This is distinct from the
468-question known-exposure sensitivity. No malformed answer, tool error or

The six-worker phase later stopped at 936 predictions / 1,407 primary slots with

## Tool-protocol limitation found without labels

The added evaluator accepts one tool call per assistant response, while the
native runtime can process multiple calls and the frozen request did not disable
parallel calls explicitly. A 936-prediction, no-label audit found 20 parallel
responses whose individual function arguments were legal, but which requested
7–8 targets in aggregate. No case met a conservative repair rule limiting a
turn's combined reading to four targets. These results are retained as failures;
no prompts, tool budget or saved predictions are changed mid-comparison. Another
59 outputs were final-turn DSML tool text without an XML answer, despite
`tool_choice=none`; independent XML parsing recovered none. These are format
outcomes, not direct evidence about the truth of the KB's claims. The final
readout must separate this constrained agent's end-to-end performance from any
claim about knowledge quality itself. A subsequent preregistered agent comparison
should make parallel-tool behavior and the final-answer contract explicit.
