# Frozen public v1.5 KB comparison

The user narrowed this takeover to testing the historical KB first; further KB-loop
iterations follow later. This is a public-benchmark readout, not a fresh generalization
experiment. No model weights, claims, historical runs, RL runtime or remote processes
are changed. No sealed final benchmark test is opened.

## Question and contract

Does the accumulated `soa_async_v1/kb_live.json` improve this solver over its original
35-claim `kb_0000` and no KB on the official v1.5 main 500 questions?

- Model: existing local Paratera configuration, `DeepSeek-V4.1-Flash-1017`, temperature
  zero, thinking disabled. Credential: execution-time `DEEPSEEK_API_KEY`; never saved.
- Dataset: the original main-500 release archive, SHA256
  `7769b0db31b9e0c12860c84d5cc05c53a45098331d4db372c2c5aec076f8be2f`.
  Preserve the original question text. Copy only public fields into jobs; store the
  grader separately. Exactly 32/500 question IDs also occur in the 450 historical
  training records. Historical corpus/lab/seed exposure is incomplete. Primary
  reporting keeps all 500; also report the 468 without those exact ID matches as
  a descriptive sensitivity check, never as verified unexposed data. Historical
  group names and official dataset IDs use different namespaces.
- Arms: N = no KB; F = original 35 claims; L = frozen accumulated 143 claims and
  77 reports. These snapshots precede this evaluation run; no new selection by its outcomes.
- Use the upstream runtime's brief solver prompt. Reports are available only via
  frozen `kb_open` lookup; save every requested target and returned evidence.
  Each call opens at most four targets and returns at most 30,000 characters,
  with an explicit truncation marker; these limits are part of registration.
- Three independent provider samples per question and arm: 4,500 predictions.
  Each has a cap of 3 calls and 3,000 total completion tokens, including tool turns.
  All arms share these limits. The final permitted call has no tools. Actual calls,
  input/completion tokens and truncations are reported separately.
- Stop on the complete grid, authentication/transport failure, STOP file, contract
  mismatch or the 13,500-request upper bound. No automatic retry of uncertain calls.
  The user authorized unrestricted monetary cost; the finite request ceiling is the
  maximum required by this fixed protocol, not a renewed legacy budget.
- Save successful raw responses before processing; resume those exact responses.
  A new run name alone cannot create new data or justify repeating a saved solve.
- Freeze source/input hashes and commit this preregistration before the first model
  request. The first real N job also verifies the completion endpoint; no paid probe.

## Measurement

Require all question × arm × repeat cells before opening the grader. Missing
transport outcomes stop the experiment rather than shrinking the scoring denominator.
Malformed or truncated actual model answers are retained and scored zero.

Average repetitions within each question. Report accuracy, all three paired
contrasts, group-cluster standard errors and fixed-seed group bootstrap 95% intervals.
Retain per-question and per-family results. Citation/opening associations are usage
telemetry; they do not identify the causal effect of an individual claim.

Published leaderboard scores are descriptive context only: their exact solver
budgets and paired predictions have not been matched. The existing local 76.2%
35-claim result belongs to a different `aiq_loop` implementation/model contract;
it is neither this run's result nor evidence for the final 143-claim KB.
