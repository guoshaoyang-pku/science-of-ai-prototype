# 首簇试点合同：冻结 Teacher 的序列预测任务

日期：2026-10-19。范围：本地 CPU 开发诊断；合同与实现先提交，再执行一次测量。实际预注册身份以运行清单中的 Git commit、合同与源码 SHA-256 为准；本文不预填提交号或宣称已完成冻结。

## 结论与决策

当前没有该任务簇的质量、candidate 训练收益、solver 迁移收益或客户付费证据。本次先测量一个随机 Transformer teacher 的条件分布，产物用于判断下一步是否值得进行候选训练设计。

本轮唯一问题：**在下述固定配置和开发样本上，该随机 teacher 的条件分布相对低阶基线有多少可学习结构？** “可学习结构”在本轮仅操作化为 teacher 分布与 uniform、unigram、bigram 的预测差距，以及删除远端历史后的分布变化；这些测量不证明有限预算的 candidate 能学到该结构。

结果没有自动通过阈值。允许结果是近均匀、主要为词频差异、低阶差异、明显上下文敏感或测量失败。单个 teacher seed 的结果不能作为商品质量或整个机制家族的结论。

## Formulation：一簇、一个题目与两层学习

簇按“生成机制＋能力目标＋评估合同”定义；随机 seed 和数据条数不单独构成新簇。本次簇名为“冻结 Transformer teacher 合成序列预测”，不把合成过程统一称为 teacher forcing。Teacher forcing 专指训练/评分时使用保存序列的真实历史预测下一 token。

| 层级 | 本轮对象 | 可以支持的范围 |
|---|---|---|
| 机制家族 | 冻结、随机初始化、因果 Transformer | 仅该生成机制的开发诊断 |
| 参数配置 | 词表 256，2 层、hidden 128、4 heads、FFN 512 | 仅该配置 |
| Teacher 实例 | 初始化 seed 101 | 仅此实例，不是跨 seed 结果 |
| 数据样本 | 独立数据随机流生成的前缀与续写 | 同 teacher 的样本差异 |

未来单题目标：solver 在公开输入和资源约束下提交 candidate 配置，由平台训练 candidate 并评分。需区分：

1. **内层 candidate 拟合：**candidate 从头训练，能否在规定资源下接近 teacher 条件分布。容量较大不保证可表示、可优化或能及时拟合；teacher 参数更少只是一条设计约束。
2. **外层 solver 迁移：**solver 使用这些题目训练后，相比对照能否在未见配置、实例或机制上更好地做研发决策。内层低损失不是外层收益证据。

本次没有运行这两层训练；只运行生成器和无需梯度训练的计数基线。

## 成立程度与冻结边界

- **解析事实：**256 类 uniform 预测的 CE 为 ln(256)，约 5.55 nats/token；同一上下文分布上，soft-target CE = teacher 条件熵 + forward KL。
- **待测量：**固定实例的熵、低阶基线差距、短历史干预变化及 sampled CE。报告数值前必须从保存产物复算。
- **待检验假设：**这些差距能被 candidate 有效学习，任务能区分研发策略，solver 收益能迁移，客户愿意采购。当前均不成立为已证实结论。

本次 train 与 audit 全部标记为 **development-only**。audit 是执行前约定的诊断样本，供本轮核对分布；结果一经查看就是开发材料，不能被包装成未见 benchmark test。后续正式验收需要独立设计、冻结并记录暴露的评估池。更换 seed、run 名或重新生成数据不会自动消除机制层面的暴露。

本诊断是新建合成环境，不使用 ArchitectureIQ 题目；不需要读取其最终 benchmark test。未来如接入该题库，另行冻结 main commit、release、group/seed/variant 和暴露记录。旧 D2 固定特征回归证据不替本任务的 CE 或 solver 收益背书。

## 方法：本次 CPU 开发诊断

### 固定参数

| 项目 | 本轮约定 |
|---|---|
| Teacher | 随机初始化 Transformer，冻结权重，因果 mask；vocab 256、hidden 128、layers 2、heads 4、FFN 512、max_positions 64；具体 norm、激活、位置嵌入和初始化以预注册源码为准并随源码 hash 保存 |
| 生成 | 前缀 16 token，各 token 独立均匀采样；续写 16 token，按 teacher 条件分布逐 token 采样 |
| 数据 | train 64 条、audit 64 条；各有 1,024 个续写预测位置，前缀不计为监督标签 |
| 随机流 | teacher seed 101、train seed 202、audit seed 303；记录库版本与执行设备，seed 不保证不同平台逐位一致 |
| 运行 | CPU、单线程；不调用收费模型，不启动 solver、supervisor 或 candidate 优化训练 |
| 基线 | uniform；train 续写标签计数的 unigram；train 真实历史最后一个 token 到续写标签的 bigram；两种计数基线均加 1 平滑 |
| 历史干预 | teacher 只保留最后 4 个历史 token，保持这些 token 原有绝对位置编号；与完整历史在相同 audit 预测位置配对比较 |

### 指标和复算口径

对 audit 每个续写预测位置，令完整历史上的 teacher 概率为 p，预测器概率为 q，保存标签为 y。对全部 1,024 个位置等权平均，使用自然对数：

- Teacher entropy：H(p) = −Σ p log p。
- Soft-target CE：CE(p,q) = −Σ p log q。
- Forward KL：KL(p∥q) = Σ p log(p/q) = CE(p,q) − H(p)。统一方向，不能与 reverse KL 混用。
- Sampled CE：−log q(y)，作为保存标签上的样本度量；它与 soft-target CE 的差异包含采样波动。sampled CE − 平均 H(p) 不应在单次有限样本上直接标为精确 KL。
- Uniform、unigram、bigram 均在同一 audit 上计算以上适用指标。逐级差距用于定位词频和一步转移能解释的部分；不预设 bigram 必须优于 unigram。
- 短历史干预以 q = teacher(short history) 计算 KL(p∥q)，并保留 sampled CE。删除历史会把 teacher 输入变为离分布干预，即便保留绝对位置，所得变化也不构成“远程记忆贡献”的纯因果识别。

本轮分母同时报告为 **1 个 teacher、64 条 audit 序列、1,024 个续写位置**。同序列 token 相关，不能把 1,024 个 token 当作 1,024 次独立 teacher 重复。若后续添加不确定性估计，应按序列重采样，跨 teacher 稳健性需独立的多 seed 设计。

### 双层预算与当前资源上限

本轮资源是一个固定 teacher、128 条生成序列、三种计数/解析基线和一次短历史诊断；不存在付费模型预算。脚本只生成约定样本，不因观察到不理想结果自动扩 seed、扩样本或启动候选训练。记录实际耗时、设备和线程；如运行中断，保留已有产物及失败原因，修复后将重试视为新的开发记录。

未来训练须分别冻结两层预算：

| 层级 | 正式实验前必须明确 |
|---|---|
| 内层训练 | 硬件型号与数量、wall time、steps、token 数、batch、精度、FLOPs 估算；编译、加载与验证计时边界；失败试验消耗。固定 steps 不能替代计算量对齐。 |
| 外层搜索 | 配置尝试数、验证查询数、solver 调用与费用、总计算量、并行度及超时；预计算、失败和重试均入账。 |

客户预算、正式质量阈值、候选训练预算与 solver 试验预算均 **待定**；本轮测量不隐含批准下一阶段。

## 失败、排除和停止规则

1. 先保存配置、身份与开始状态，再生成数据；输出目录不得覆盖已成功保存的诊断。
2. 概率不归一、非有限值、序列或维度不符、复算不一致均为测量失败；不得通过删点获得合格结果。
3. 低阶基线表现差或好都要保留。单次结果不理想不能触发 seed 搜索；后续修改必须说明由哪项开发证据驱动。
4. 近均匀或低阶可解释不自动等于“坏题”，而是对该实例能力目标的限制；在目标与阈值未定义前不发合格证。
5. 不读取或修改旧 v2 快照、旧 Loop/Jobs/publisher、RL trainer、checkpoint、历史 run、远程进程；不重跑旧成功解题，不增加主页 block。

### 三类责任与交付

负责人统筹一个问题、验收口径和预算，生产与最终验收由不同责任人承担；同一人兼任时需显式披露，不能称独立验收。

| 责任 | 交付物 | 验收依据 |
|---|---|---|
| 任务开发 | 生成器、设计空间、参数/seed 清单、开发诊断和失败记录 | 配置可追溯、生成机制可说明、基础概率和标签检查通过 |
| 独立评测 | 复算脚本、基线/漏洞检查、暴露账、后续独立评估合同 | 从保存产物复算；保留分母；确认阈值和留出方式支持实际主张 |
| 平台交付 | 可运行包、运行说明、资源账、产物索引、客户试用记录 | 新机器可复现、成本可核算、客户验收与内部开发指标分开 |

以“通过独立验收的机制簇/人周”、每簇成本、失败率与返工率衡量产能；生成样本数量不是产能质量指标。

商业文档中的访谈与价格引用尚未核验，不作为市场事实。2 万美元/簇是报价假设，需明确普通许可、独占、定制和持续更新的权利范围。100 簇 × 2 万美元 × 3 家 = 600 万美元只是全部交付、全部售出的销售额情景；一次性许可不能称 ARR。只有明确年度持续权益与订阅收入时才使用 ARR。“20 高质量＋100 普通”与“年度 100 簇”数量口径须统一，正式质量门槛仍待定义。
