# AIQ 许愿池初稿

2026 年 10 月 27 日 · 面向项目组讨论与共同补充

AIQ 希望衡量一种训练直觉：给定数据、候选模型及训练设置，能否在看到训练结果之前，预测哪个方案表现更好。围绕这个目标，我们还希望理解预测为什么成立、在哪些条件下失效，以及经验能否积累成帮助新任务的知识。

本许愿池按八个 aspect 组织。每节先解释这一方面研究什么，再列出现有材料支持的内容、尚未解决的问题和候选愿望。团队可以据此补充需求、挑选问题，并明确下一步交付物。

**已确认的文档要求：** 将 aspect 解释与许愿放在同一份文档中。**八个 aspect 的分类、下列全部候选愿望及优先顺序均为建议，未经会议确认，也未分配负责人或实验预算。** 这里没有将示例补写成 10 月 26 日会议的原始意见。

## AIQ 在问什么

ArchitectureIQ 的基本题目包含一个数据实例和若干训练配方。配方由模型、优化器、损失函数和训练预算等组成；答题者根据题目提供的信息预测最终评价指标最好的候选。答案来自实际执行生成的训练代码，而不是出题者凭经验指定。[S1][S2]

把指标统一写成越小越好，问题可以简写为：

\[
c^*=\arg\min_{c\in\mathcal C}M(D,c,B_c).
\]

这里，\(D\) 是数据实例，\(\mathcal C\) 是题目的候选集合，\(B_c\) 是候选自己的训练预算，\(M\) 是按题目协议汇总的评价指标。这只是任务定义，不是关于训练规律的新发现。它也提醒我们：“哪个模型最好”必须带上数据、训练方法、预算和评价口径。

项目中有三个相关层次，需要分别说明其产物与证据。

| 层次 | 核心问题 | 主要产物 |
|---|---|---|
| ArchitectureIQ benchmark | 人或模型能否预测训练配方的表现？ | 题目、执行所得答案、评测协议与成绩 |
| KB 辅助解题 | 先前积累的知识能否帮助后续预测？ | 冻结的知识库输入、解题记录、对照评测与知识修订 |
| Science of AI 受控研究 | 哪些训练现象能转化成可检验、可复用的规律？ | 预注册、实验结果、反例、适用范围与研究报告 |

上游 README 报告了训练直觉、推理、知识积累和数据依赖方面的结果；本仓库也保存了研究与 KB runtime。二者的实验合同不同：不能用上游的知识积累结果，替代本仓库新协议下的 solver 收益验证。[S1][S5][S6]

## 八个 aspect 的关系

前五个 aspect 解释训练配方为什么可能表现不同；第六个确保答案和评测可信；第七个讨论如何形成可检验的解释；第八个讨论如何积累和迁移知识。

| Aspect | 核心问题 | 与其他方面的联系 |
|---|---|---|
| 数据与任务 | 模型究竟需要从数据中学会什么？ | 决定结构、训练方法和目标是否合适 |
| 模型结构 | 模型能表达什么，又倾向于先学什么？ | 与数据结构、优化和预算共同决定结果 |
| 优化与训练动力学 | 模型如何随训练时间改变？ | 连接初始状态、训练过程和最终表现 |
| 目标与评价指标 | 训练在优化什么，我们最终重视什么？ | 决定“更好”的具体含义 |
| 资源与公平比较 | 在什么资源约束下比较方案？ | 改变更新次数、可达性能和候选排名 |
| 答案与评测可信度 | 观察到的差异是否可信？ | 为所有能力与收益主张提供依据 |
| 推理与解释 | 能否从已知条件推出可检验预测？ | 将经验连接到机制与反例 |
| 知识积累与迁移 | 已有经验能否帮助新的问题？ | 检查知识的复用价值与适用边界 |

下文的“已有”指相应来源明确记载的设计、能力或结果；“未决”指现有证据没有解决的问题；标有“建议”的愿望及验收方式均是供讨论的方案。

## 数据与任务

### 这个 aspect 是什么

数据不仅是样本数。输入分布、目标函数、噪声、变量之间的交互、分类边界或序列结构，都决定了学习任务。例如，主要由单变量效应构成的目标，与依赖变量乘积的目标，即使样本数相同，也可能需要不同的表示与训练过程。

AIQ 区分 dataset family 与 dataset instance：前者定义一类任务的生成方式和评价方法，后者是具体生成的数据。同一道题的所有候选使用同一数据实例，才能把性能差异归因于候选配方。[S2]

### 已有材料与未决问题

固定版本 README 列出单变量回归、多变量回归、bigram 下一词预测、合成表格分类、XOR 分类和双螺旋分类六类任务；实际启用哪些任务取决于 profile。README 还介绍了 data-flip 设计：让获胜方案依赖数据变化，检验答题者是否真的利用了数据信息。[S1]

本仓库 D2 的固定特征回归研究说明，同一种时间缩放假设不能简单跨任务使用。允许每个任务单独拟合系数后，固定指数为 1 的模型在扩展条件上合计通过 1232/2700，12/12 个任务与特征条件都未达到预定 80% 门槛。这里以预测最低点时间为实测估计的 0.5–2 倍作为通过，边界最低点计失败；结果不等于所有训练任务都不存在简单规律。[S4]

未决问题是：哪些可观测的数据性质足以帮助预测训练结果？数据 family 名称可能过粗；只记住某类题通常由哪个候选获胜，也不能解释数据改变后的排名。

### 建议愿望 W01 预测数据变化引起的排名变化

**我希望 AIQ 能在候选配方保持不变时，解释并预测改变数据后，哪个方案会获胜。** 这样才能检查模型是否依赖数据特征作判断。

- **具体问题：** 在一个选定 family 内，只改变目标的交互结构或噪声水平，预测候选的获胜关系是否改变。
- **建议验收：** 在事先冻结的独立分组上，同时报告总体准确率、真实翻转组与未翻转组表现；与忽略数据信息的基线比较，保留未能预测的翻转。
- **最小下一步：** 先写一页数据对照规格，列清改变项、固定项、可提供的信息和分组方式。涉及既有题池时先核对暴露记录。
- **依赖：** W06 的评测合同。相关研究入口为 D2、D6、D7。

**补充愿望 W01b〔建议〕：** 建立“数据性质卡”，用目标结构、噪声、输入分布等说明题目，而不只使用 family 标签；先为一类开发任务示范。

## 模型结构

### 这个 aspect 是什么

结构决定模型能表示哪些函数，以及训练时各部分如何相互影响。深度、宽度、激活函数、偏置、归一化和残差连接，都可能影响表现。表达能力更强，不自动意味着在有限预算内训练得更好。

AIQ 中的 model axis 表示候选结构的差异。要把题目称为单独比较结构，就需要控制其他比较轴；其中 batch size 也必须一致。模型类型与任务的兼容性由任务插件和 profile 共同约束。[S2]

### 已有材料与未决问题

本仓库的 D3、D5、D8、D10、D11、D13 分别涉及容量、层归一化、激活与偏置通路、深度传播、宽度及线性网络中的连接结构。它们提供的是各自受控条件下的结果，不能合成“加宽有益”或“LN 总是更好”的统一规则。[S3]

D5 尤其需要区分“测到收益”与“解释收益”。旧研究用 chord 指标衡量改变标签偏移后误差形状的变化。在复用实际 batch64 顺序的 20 对条件中，固定初始化核对 LN 与无 LN 的 chord 差值方向，与保存真实训练的方向匹配为 0/20；这表示该近似未能恢复这一特定指标的方向，不是整条训练轨迹的匹配率。[S7]

### 建议愿望 W02 给结构建议附上适用条件

**我希望 AIQ 能说明什么时候值得使用某个结构组件，以及什么时候这条建议会失效。** 首个问题可以选择 LN，也可以由团队替换成更重要的组件。

- **具体问题：** 在预先指定的同宽度配对中，哪些条件足以解释或预测加入 LN 后的收益方向？
- **建议验收：** 先注册收益指标与方向预测，再检查独立条件；收益、无明显差异和反向结果全部保留。若声称因果解释，还需要能区分竞争解释的干预。
- **最小下一步：** 汇总已有 D5 条件、反例和权重衰减问题，形成机制对照表；先核对既有任务状态，避免重复立题。
- **依赖：** 明确结构比较是否同时匹配宽度、参数量或其他资源。相关入口为 D5。

**补充愿望 W02b〔建议〕：** 将 D11 的固定特征维数研究与真正可学习网络的宽度研究分开，先定义后者的测量对象和可比较条件。

## 优化与训练动力学

### 这个 aspect 是什么

优化器、学习率、动量、batch size 和训练时长共同决定模型怎样移动。两个候选可能最终接近同一水平，却在早期速度上差异很大；也可能先后交换排名。

研究训练动力学，就是解释损失曲线、学习速度、稳定性及不同阶段之间的变化。例如，累计学习率相同是否意味着相同训练进度，需要检验，不能只靠换算时间单位来回答。

### 已有材料与未决问题

D1 已记录等效训练时间的反例；D4 和 D12 研究单段或多段 sigmoid 曲线描述的适用范围；D9 研究小批量噪声。D9 在两个受控条件中观察到 B8→B4→B2 时最低点延后，但这不足以建立连续的 batch-size 定律。[S3]

一个关键未决问题是：早期能观察到的信息，是否足以预测后期变化？训练完成后拟合整条曲线，只能说明描述能力；真正的预测必须提前冻结可用信息。

### 建议愿望 W03 用早期信息预测后期训练变化

**我希望 AIQ 能根据有限的早期轨迹，预测后续的学习速度或候选排名变化，并说明不确定性。**

- **具体问题：** 首轮只选一种预测目标，例如在指定预算终点预测候选排序，不同时承诺预测完整曲线和过拟合时刻。
- **建议验收：** 固定早期观测窗口和输入字段，与按当前 loss 排序、保持当前趋势等简单基线比较；单列后期发生排名反转的失败案例。
- **最小下一步：** 用允许使用的开发轨迹制定输入格式和评分方式。已经看过完整结果的轨迹只能用于开发，不能作为新的盲测。
- **依赖：** 这是增加早期观测的扩展任务，需与原始静态 AIQ 题分开报告。相关入口为 D1、D4、D6、D9、D12。

**补充愿望 W03b〔建议〕：** 对“等效训练时间”建立反例清单，明确其比较的是参数位移、损失进度还是泛化表现，避免把不同对象折成一个数。

## 目标与评价指标

### 这个 aspect 是什么

训练 loss 决定更新参数时优化什么；selection metric 决定评价时怎样排名。二者可能不同。即使都叫 MSE，也要区分是在训练样本、独立样本、带噪标签还是干净目标上计算。

因此，“训练更好”“泛化更好”和“更早达到某个水平”是不同主张。题目的评价对象改变后，答案也可能改变。AIQ 将 loss 与由 dataset family 定义的 selection metric 分别保存和使用。[S2]

### 已有材料与未决问题

D2 研究的是固定特征、平方损失、全批量梯度下降下的风险曲线。在 3137 个内部最低点中，只有 766 个满足对训练噪声取期望的带噪训练 MSE 不高于初值的 10%；没有达到预注册的“至少 90%”阈值，因而反驳了该具体预测。这一计数描述噪声平均后的量，不是单次训练曲线的统计。[S4]

这里的最低点来自指定窗口内的格点搜索与局部精化，不保证是第一次局部回升；研究使用的是独立合成 validation，并非最终 benchmark test。现有结果也没有建立仅凭训练信息即可实施的早停方法。[S4]

### 建议愿望 W04 在不看未来结果时提出早停规则

**我希望 AIQ 能判断什么时候继续训练的收益已经不足，并给出可执行的停止建议。**

- **具体问题：** 先在固定特征回归内，限定只能看到训练阶段允许的信息，预测何时停止。
- **建议验收：** 除停止时间误差外，报告停止点相对事后最佳点的额外风险，以及过早、过晚停止的比例；与预设固定预算基线比较。事后最佳点只用于评分。
- **最小下一步：** 列出部署时可见与不可见的量，检查候选规则是否偷偷依赖验证标签、已知噪声或未来曲线。
- **依赖：** 先确定目标是单次训练的最低点，还是噪声平均风险的最低点；两者不能互换。相关入口为 D2、D7。

**补充愿望 W04b〔建议〕：** 为每个研究结果配一张指标释义卡，写清数据划分、标签是否含噪、聚合方式及越大还是越小更好。

## 资源与公平比较

### 这个 aspect 是什么

AIQ 的训练预算定义为 total_samples_seen，即 training_steps × batch_size。它衡量累计处理的样本量，不等于独立数据量，也不等于运行时间或计算量。相同预算下，batch size 不同，参数更新次数就不同。[S2]

同一个 candidate set 共享这一预算；跨 set 的题可以比较不同预算，但必须明确每个候选的预算。因此，“公平”需要先说明公平在哪个维度，不能只写“训练相同时间”。[S2]

### 已有材料与未决问题

AIQ 已有显式预算与跨预算比较的协议。尚需针对具体研究决定：我们希望在相同样本处理量、相同步数、相同参数量还是相同计算成本下比较。这些标准回答不同问题，不能自动相互替代。

### 建议愿望 W05 预测不同预算下的候选选择

**我希望 AIQ 能给出随预算变化的选择建议，而不是把某个候选固定称为最好。**

- **具体问题：** 在固定数据与候选定义下，预测低预算和高预算时的排序是否相同。
- **建议验收：** 分预算报告预测表现，并单列真实排名交叉是否预测正确；记录参数量和运行条件，防止把不同资源口径混在同一结论中。
- **最小下一步：** 先制定预算对照表，明确固定 total_samples_seen 还是固定 steps，并说明为什么该口径符合使用场景。
- **依赖：** 与 W03 的时间过程和 W06 的比较合同相连；新增测量需另定资源预算。

**补充愿望 W05b〔建议〕：** 在文档中同时展示样本处理量、更新次数与参数量；如果使用运行时间作比较，再补充设备和测量协议。

## 答案与评测可信度

### 这个 aspect 是什么

可信评测需要两层保证。首先，题目的答案可信：显示给答题者的代码应与实际执行的代码一致，候选之间的差距需要按协议处理随机性。其次，能力判断可信：答题者不能提前接触答案，开发过程也不能反复利用保留条件改规则后仍把它称为新验证。

AIQ 的核心约束是执行生成代码得到 ground truth；组题过程利用已保存结果和显著性规则选择候选，题目不暴露最终指标或曲线。随机种子数量、阈值和启用任务取决于具体 profile，不能把某个配置当成所有 release 的共同属性。[S1][S2]

### 已有材料与未决问题

本仓库明确要求新 solver 实验选择 release，核对 group、seed、variant 及历史暴露。换一个运行名或随机种子，不能自动得到独立新数据。KB runtime 支持解题时冻结知识输入，答案在后续发现阶段才揭示。[S5][S6]

历史宏观检查是研发读数；最终保留集不能成为反复选择规则的工具。现有基础设施能保存协议，并不替代对具体实验独立性和收益的审查。[S5]

### 建议愿望 W06 为每项能力主张建立评测合同

**我希望团队在讨论“AIQ 提升了什么”时，能明确指出是哪种能力、在哪些独立条件上、相对什么对照得到的提升。**

- **具体问题：** 为下一项拟验证的能力，写清 release、分组、暴露、输入、答案揭示时机、基线、评分、失败处理和预算。
- **建议验收：** 另一位成员仅凭合同就能判断哪些记录可用于开发、哪些可用于验证；来源不明的条件不能默认为未暴露，失败与无法解析结果有明确去向。
- **最小下一步：** 用一项候选愿望填写合同并做文档审阅，不启动评测，也不读取最终 test 内容。
- **依赖：** 为 W01、W07、W08 等提供共同前提。

**补充愿望 W06b〔建议〕：** 将“知识条目数量”“完成任务数”“可复算结果”“独立预测收益”分别登记，避免用流程完成度代替科学进展。

## 推理与解释

### 这个 aspect 是什么

预测正确与解释可靠需要分别检验。一次选对答案，可能来自有用的机制，也可能来自偶然相关；一段流畅解释，也可能无法预测改变条件之后会发生什么。

可检验的解释应该指出关键变量、预测方向、成立条件，以及什么结果会推翻它。例如，声称某种结构通过改善某个几何量提升训练，就需要说明改变该几何量时训练应怎样改变，并与其他解释区分。

### 已有材料与未决问题

上游 README 将推理是否具有可组织结构列为研究主题，并展示了从 benchmark 中提炼的分析策略。本仓库则要求一轮一个可检验问题，在实验前注册预测，保留失败、反例和范围。[S1][S6]

D2 提供了一个区分定义、解析关系和经验定律的例子：在指定冻结特征模型中，风险可分为信号误差与噪声响应；这不自动推出最低点时间与噪声精确成反比。经验缩放律仍需独立检验，扩域失败也必须保留。[S4]

### 建议愿望 W07 让解释产生可以失败的预测

**我希望 AIQ 的解释能指出一个尚未看到结果的条件，并在该条件上给出明确预测。**

- **具体问题：** 选一个现有解释，为它写出一个与竞争解释结论不同的条件；冻结预测方向、指标和误差标准后再验证。
- **建议验收：** 分开记录选项预测是否正确、机制预测是否成立；机制失败时保留原解释及修订原因，不能因为最终选项答对就判定解释正确。
- **最小下一步：** 从 D2 的缩放失败或 D5 的竞争机制中选一例，写出两种解释各自预期什么。先审查是否存在可区分它们的观测或干预。
- **依赖：** W06 的信息与评测边界，以及预注册早于实验的记录。

**补充愿望 W07b〔建议〕：** 每条解释附上“最强反例”和“下一条可区分预测”，使知识修订围绕证据发生。

## 知识积累与迁移

### 这个 aspect 是什么

知识库的价值在于让后续任务更容易判断，同时让错误认识能够被修订。每条知识至少应说明适用条件、结论、证据与反例；“常常有效”的经验不能省略它来自哪些条件。

迁移则进一步追问：知识在原题之外是否仍然有用？同一题换顺序、换一次模型采样，和换到独立数据组或新任务，不是同一种验证。

### 已有材料与未决问题

本仓库 runtime 支持解题时冻结 KB，随后揭示答案开展发现；研究知识可新增、修订、合并和删除，并保留发起与应用轮次及谱系。研究 KB 与供 solver 使用的稳定版本也有分开管理的协议。[S5][S6]

这些能力使“知识是否有用”可以被评测，但本仓库现有交接并未建立新协议下的 solver 收益或广泛泛化收益。上游报告的知识积累实验与本仓库研究结果应分别归属，不能把两者拼成未经验证的完整效果链。[S1][S5][S6]

### 建议愿望 W08 检验知识对独立新任务的帮助

**我希望从研究中积累的少量知识，能够在独立新任务上帮助 solver，并明确指出哪些知识没有帮助或造成误导。**

- **具体问题：** 冻结一个小型 KB，在合规的独立题组上比较有 KB 与无 KB 的配对结果，控制模型设置、题目与作答资源。
- **建议验收：** 报告配对分数差及不确定性、各任务组表现和退化案例；改进主张需满足预注册判据。被引用次数只作使用记录，不能单独证明知识有效。
- **最小下一步：** 从已有研究中选出适用范围清楚的知识，写出 KB 快照规范和对照合同；未找到合适独立题组时先保留为待验证。
- **依赖：** W06、明确模型与调用预算，以及可用的未暴露 release。这一愿望目前不是启动 solver 的指令。

**补充愿望 W08b〔建议〕：** 比较完整 KB、压缩 KB 和无 KB；在资源口径明确后，检验压缩是否保留帮助，并记录被压缩掉的条件和反例。

## 建议优先讨论的三项

建议按“先把验证条件讲清，再确定科学问题，最后检查知识效用”的顺序讨论。优先讨论不等于优先启动实验。

| 顺序 | 候选 | 为什么先讨论 | 下一份交付物 |
|---|---|---|---|
| 1 | W06 评测合同 | 先确定什么证据能支持能力提升，避免后续愿望使用不同口径 | 一份可审阅的合同及未决项清单 |
| 2 | W01 数据变化与排名变化 | 直接对应训练直觉是否依赖数据，易于明确固定项与改变项 | 一个 family 内的数据对照规格 |
| 3 | W08 知识对新任务的帮助 | 连接受控研究与 AIQ 解题，但受独立题池及预算约束 | KB 候选清单、配对对照方案与预算估计 |

W03 和 W04 是重要的长期愿望，但先要解决早期输入、单次轨迹与期望风险等定义。W02 涉及已有 D5 后续任务，下一步应先核对其产物，再决定补充问题。

## 团队如何补充和认领

新愿望先写三句话即可：**我希望 AIQ 能什么、为什么重要、一个具体例子。** 不要求提出者先完成实验设计。整理时保留原话，再附上可检验版本；跨 aspect 的愿望只保留一份主记录，并列出关联方面。

建议采用以下记录格式：

| 字段 | 填写内容 |
|---|---|
| 原始愿望与来源 | 原话、提出者或会议记录链接；本稿示例来源统一为建议 |
| 主 aspect 与关联 aspect | 主要归属及必要的交叉联系 |
| 可检验问题 | 一轮能够回答的具体问题，不预定答案 |
| 已有依据与反例 | 对应文档、保存结果、失败和适用范围 |
| 成功与失败标准 | 指标、对照、分母、阈值以及无法判断的处理方式 |
| 最小下一步 | 下一个具体交付物，例如合同、证据表或预注册草案 |
| 状态与认领人 | 建议、待澄清、已认领、已制定实验计划、已有结果或暂缓 |
| 资源与依赖 | 数据暴露情况、模型或计算预算，以及需先完成的工作 |

本稿 W01—W08 及八条补充愿望均为“建议”，认领人和预算留空。只有完成问题、对照、判据及资源的明确约定后，才转为具体实验计划。已保存的成功解题不重跑，最终 benchmark test 不用于本轮文档整理。

## 尚需团队决定的问题

1. 首轮最关心哪种能力：静态训练直觉、允许早期观测的预测，还是带反馈的知识积累？它们需要分别设计输入与评测。
2. 希望首先服务谁：研究人员理解现象、solver 提升解题，还是使用者选择训练配方？这个选择会影响验收指标。
3. 哪一类数据和候选适合作为首个小范围问题？这需要结合已有证据、独立条件与可用资源确定。
4. 哪些候选愿望与会议原话一致，哪些需要修改、删除或新增？在获得原始记录前，本稿不替团队回答。

材料中另有一处协议口径待核对：上游 README 与 AGENTS 对单个 candidate set 内 batch size 是否可变的描述不同。本稿仅使用两者不冲突的约束，不据此推断实际采样行为；制定具体实验时，应在固定版本下核对实现和 profile。[S1][S2]
