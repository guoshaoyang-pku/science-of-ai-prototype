# 报告语言与结构标准 — L4 给人汇报的风格

来源：用户的 report_to_human 四层汇报体系（完整技能副本在 `report_to_human_skill/`，含 STE100 写作清单与 panel 模板）。四层含义：L1=STE 风格散文，L2=图标/图示，L3=HTML panel，L4=聊天里一句话结论+链接。本文件是其中适用于方向 `report.md` 的**操作版**：report 的散文按 L1 纪律写、按 L4 的"给人汇报"口吻组织——读者只读"结论"和"成立程度"两节就能拿走 90% 的图像。

## 结构（固定骨架，与 AGENTS.md 一致）

```
# Dx：<方向名>
## 结论           ← 开头。平实句子直说已确立与被推翻的规律，一条规律一条，带关键数字
## Formulation    ← 核心公式（允许花括号分段），逐符号定义含义+单位
## 成立程度       ← 判据与通过率、误差范围、边界/阈值、保留反例、适用与未测范围
## 方法与条件     ← support
## 失败与反例     ← support
## 未决问题       ← support
## 证据           ← support；全部文件与 commit 链接只准出现在这一节
```

## 语言规则（L4 风格，逐条硬要求）

1. **结论先行**：每节、每段先给答案，再给理由和条件。
2. **短句**：一句只装一个事实。长句拆开。不用多层从句。
3. **平实词**：行话首次出现必须当场解释（一句话或括号内），例："Rayleigh 商（目标加权的平均特征值）"、"切线模型（把网络在初始化处线性化）"。
4. **数字代替形容词**：写"57/60 在 2 倍内"，不写"绝大多数"；写"误差 ≤9e-16"，不写"极准"。禁用：显著、非常、相当、明显、大幅——除非紧跟具体数字。
5. **主动语态**：写"实验显示"，不写"被实验所显示"。
6. **无填充**：不写动机章、展望章、"本节将介绍"。表格之后不用散文复述表格。结尾不喊口号。
7. **认知标签诚实**：测得的 / 解析导出的 / 推测的，三种措辞不得混用。被推翻的预测也要进"结论"节（一行即可），细节放"失败与反例"。
8. **结论与成立程度两节不出现**文件路径、commit 号、轮次号；链接全部放"证据"节。

## 自查 checklist（重排或新写 report.md 后、落盘前逐项过）

- [ ] 节顺序符合骨架；"结论"在最前
- [ ] 每条结论带关键数字与范围词（recipe/维度/优化器/目标类型）
- [ ] 行话首次出现处都有解释
- [ ] 无未量化的程度形容词
- [ ] "结论""成立程度"两节无文件路径/commit/轮次号
- [ ] 原报告的全部数字保留（允许格式归一，如 .9526→0.9526）
- [ ] 失败预测与反例保留、未被弱化
- [ ] 不新增任何未经测量的 claim

## 补充纪律（用户 2026-10-07 21:0x 批评后追加）

- **不跑题**：报告回答 task.md 的核心问题。"我测了什么"不等于"该答什么"；与核心问题无关的成果进 support，不进结论区。
- **人话检验**：结论节每一条目 = 一句主张（≤25 字为佳）+ 一句数字证据。连续出现两个未解释符号即不合格。把结论节单独读一遍：像不像在给同事口头汇报？不像就重写。
- **公式先行**：核心问题能用公式回答时，结论第一条就是公式（花括号分段允许），公式下一行逐符号一句话定义。
